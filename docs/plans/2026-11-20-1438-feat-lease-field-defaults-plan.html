Goal Capsule

Objective: a PM generates a residential rental agreement for a new renter with no blank required field except the R8 trust account details and R3 fields with no source, which the confirm step flags without blocking; every value is real data, a stated default, or a value the PM confirmed.

Product authority: Stuart (dialogue 20/11/2026) > Requirements (R-IDs) > Key Decisions. Scope is the residential rental agreement only. The double-check approval flow is a separate brainstorm and not active scope.

Means: spec defaults plus a server-enforced confirm gate, with applicationAI read through a new provider (KTD1, KTD4, KTD6).

Open blockers: none for building. U6 needs an applicationAI agent token for forms_fill before live use. The trust account details (R8) come later from Stuart; until then the section 8 bank details stay blank and flagged.

Lease Field Defaults - Plan1
Product Contract

Product Contract

Summary

Add sourced values and defaults to the lease fields that print blank today. Add a confirm step before the PDF, where the PM checks the defaults and answers the "ask PM" items.

Problem Frame

Leases print with blank fields. Most of these fields exist in the form, but nothing fills them and nothing prompts the PM. A blank lease field is a compliance risk and costs the PM a manual fix.

Requirements

IDRequirement
R1.Agreement date defaults to today. The PM confirms it on the confirm step (R11).
R2.For a new lease, the PM picks the approved application for the property address from applicationAI. Its applicant name, phone and email fill renter 1.
R3.Renter fields and section 9.2 details that applicationAI does not hold come from GEA CRM. A field with no source is shown on the confirm step for the PM to type.
R4.Length of agreement defaults to 12 months: the end date is the start date plus 12 months, less one day. The PM confirms it.
R5.Rent prints in dollars with cents, for example $3,867.00.
R6.First rent due date defaults to the start date.
R7.The bond amount prints in dollars with cents. The bond due date defaults to the start date.
R8.Section 8 ticks these preferred payment methods by default: bank transfer (EFT), DEFT/BPAY and Centrepay. The GEA trust account details print when Stuart supplies them.
R9.Rental provider service of notices by email defaults to Yes, with propertymanagement@grantsea.com.au.
R10.Urgent repairs contact is Grants Property Maintenance, 0438 100 545, and propertymanagement@grantsea.com.au.
R11.A confirm step runs before the PDF. It shows every default from R1 to R10 and asks for owners corporation, condition report and special conditions. The PDF does not generate until the PM confirms each item.
R12.The signature page prints each renter's name. The signature boxes stay blank, and the PM signs by hand.
Lease Field Defaults - Plan2
Product Contract

Key Decisions

  • KD1. applicationAI is the first source for a new renter, and GEA CRM is the fallback. The fetched PropertyMe tenancy holds the outgoing renters, so it never seeds a new lease. Session-settled: Stuart, 20/11/2026.
  • KD2. Each "check with PM" item is confirmed on a screen before the PDF, not fixed after the PDF. Session-settled: Stuart, 20/11/2026.
  • KD3. The match from application to property is by address, chosen by the PM. applicationAI stores no PropertyMe or CRM ID.

Key Flow

F1. The PM opens a new lease for a property. The app lists the approved applications for that address, and the PM picks one (R2). The app fills fields from applicationAI, GEA CRM and the defaults (R3 to R10). The confirm step shows each value and each "ask PM" item (R11). The PM confirms them, and the PDF generates with the renter names on the signature page (R12).

Acceptance Examples

  • AE1. Covers R4, R6, R7. Start date 01/12/2026, no PM change: end date 30/11/2027, first rent due 01/12/2026, bond due 01/12/2026.
  • AE2. Covers R5. Rent 3867 monthly prints as "$3,867.00 per calendar month".
  • AE3. Covers R11. The PM leaves "owners corporation" unanswered: the app does not generate the PDF and names the open item.
  • AE4. Covers R3. There is no current address in applicationAI or GEA CRM: the confirm step shows the field empty and marked for the PM to type.

Scope Boundaries

  • No data writes to applicationAI, GEA CRM or PropertyMe. U7 adds one read-only endpoint in applicationAI.
  • No e-signature on the lease signature page.
  • Not in scope: the double-check approval flow, and leases other than the residential rental agreement.

Dependencies / Assumptions

  • applicationAI (TenantScore, GEA_PM/GEA_PM_applicationAI) masks phones in its existing agent API and filters on scoring status, not pipelineStatus. forms_fill reads only the U7 lease-handoff endpoint, with its own scoped token.
  • An application holds one applicant name, phone and email. Co-renters, current address and emergency contacts are not columns. These are gaps for the applicationAI project.
  • The maintenance number comes from the GEA LLM phone directory (gea-llm/knowledge/directory/phone-directory.md).

Outstanding Questions

  • Deferred to Planning: whether rawExtraction in applicationAI holds the current address or co-applicants, and if it can be read safely.
  • Deferred to Planning: the GEA trust account BSB and account number (R8). Stuart supplies these later.
Lease Field Defaults - Plan3
Planning Contract

Planning Contract

Product Contract preservation: Product Contract unchanged except Scope Boundaries now notes the U7 read-only endpoint (approved by Stuart, 20/11/2026). The "no writes" boundary still holds for data.

Key Technical Decisions

  • KTD1. Build a lightweight confirm step; adopt no framework. docassemble, SurveyJS and Form.io each own the UI or server. Copy their pattern only: each item listed with its value, source and an Edit link, plus a per-item confirm flag.
  • KTD2. Stdlib only for defaults; no new dependency. End date = same day next year less one day, via calendar and datetime. A 29/02 start ends 28/02. Money uses Decimal with f"${v:,.2f}". Session-settled: Stuart, 20/11/2026 (leap-year rule).
  • KTD3. Field precedence: PM edit on the confirm step > applicationAI > GEA CRM > default. Each field carries its source so the review screen can show it. Session-settled: Stuart, 20/11/2026.
  • KTD4. The server enforces R11, not only the browser. /fill for the lease returns 422 unconfirmed_items naming each open item. This reverses KTD3 of docs/plans/2026-08-27-001-feat-lease-entry-wizard-plan.md ("no separate confirm step").
  • KTD5. Agency-wide defaults (maintenance contact, payment methods, e-service email) live in forms_fill/fixtures/gea_agency.json beside the existing payments key, read through load_agency_config. No hard-coded contact details in spec code.
  • KTD7. The confirm gate covers every residential rental agreement fill, from any caller, so R11 cannot be bypassed. confirmed is popped in api.py fill() like idem_key, because FillRequest forbids extra keys. The confirm list is one constant, CONFIRM_ITEMS, in the lease spec: the R1 to R10 defaults plus owners_corp, condition_report and special_conditions. U4 and U5 both use it.
  • KTD8. Renter PII stays narrow. U7 needs a dedicated lease-handoff token scope issued only to forms_fill, read from APPLICATIONAI_AGENT_TOKEN (Railway only, never committed or logged). The forms_fill search route needs a signed-in agent session (not the machine token), a minimum address length of 8, and returns only name, phone, email, lease start and rent. Error envelopes carry codes only; no phone or email is logged. forms_fill sends the acting agent in an X-Acting-Agent header, and U7 writes it to AgentReadLog.
  • KTD6. applicationAI is reached through a new provider with an explicit HTTP contract, timeout and error envelope. The existing masked agent API stays unchanged; U7 adds GET /api/agent/v1/lease-handoff for pipelineStatus = owner_approved only.
